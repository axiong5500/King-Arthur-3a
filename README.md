# King-Arthur-3a · 亚瑟王中王

「亚瑟王中王」——一款基于浏览器的国产 3A FPS 演示作品（WebGL 实时渲染），单文件 HTML，双击即可运行。

横屏适配版：[King-Arthur-3a-App](https://github.com/axiong5500/King-Arthur-3a-App) · 在线试玩 https://axiong5500.github.io/King-Arthur-3a-App/

## 玩法

- 港区主控已封锁泊位，切断堆场、仓库、码头三处中继
- 空中有机械飞鸥，地面有机械猎犬，三处中继全部断开后前往撤离艇
- 键鼠：瞄准 / 射击：左键 / 交互（切断中继）：按住 E / 暂停：Esc
- 触屏：左半屏摇杆移动，右半屏拖动转向，右下开火键（按住后在键上滑动可边打边转向）

## 运行

直接打开 `index.html`，或起一个静态服务器：

```bash
python -m http.server 8080
```

## 枪械皮肤

首页与暂停菜单都能进入「PAC-9 涂装库」，共六套：出厂黑、沙漠灰、都市灰、亚瑟金、极地白、猩红。点选即时生效，选择记在本机（localStorage），重新开始任务后仍然保留。

涂装只改武器的 5 个材质（阳极氧化件、磷化件、聚合物件、哑光面、弹匣），不动模型与刻字，所以任何配色下机加工细节都在；「出厂黑」是恢复原值的基准，切换回来不会有色差累积。

## 天气系统（源码保留，成品未启用）

`weather-src/` 里是一套完整的动态天气：六种天候（细雨、破晓晴、阴天、暴雨、雷暴、海雾），光照、天空色、雨量、地面湿度、远景雾一起渐变，55～100 秒自动换天，游戏内按 `K` 循环切换，面板可选。

**当前 `index.html` 未注入这一层**，只在仓库里保留源码，需要时可以随时重新注入（见下方「构建」）。不启用的原因是暴雨、雷暴在低画质下的观感还没调到位：雨量超过 0.6 会糊屏，闪电也一度借用引擎的 flash 通道把画面压黑，虽然改成了自主抬亮，但缺少真机长时间验证。

天气层的实现要点记在这里，避免以后重建时重复踩坑：雨量不能走官方 `setRain()`（受相机所在区域限制，外部调用不生效），要在渲染钩子里覆盖 `rain`/`rainSplash` 两个网格；闪电不要写 `post.flash`，改成临时抬 `sun.intensity` 与曝光、把天空色往白里拉。

## 双人联机（`mp/`，实验版本）

在线：https://axiong5500.github.io/King-Arthur-3a/mp/

一份独立的联机版本，不影响上面的单机成品。打开后点右下角「双人联机」（或按 `M`）：一人「创建房间」拿到四位房号，另一人「加入」输入房号即可进同一局。

架构是**房主权威**：房主本机照常模拟敌人 AI，把玩家与全部敌人的位置、朝向、血量按 20Hz 发给队友；队友本机冻结敌人的 `_update`，只负责渲染与射线反馈，敌人位置由网络插值驱动。队友开枪时把射线起点与方向发给房主，由房主用 `enemies.raycast` 裁决，再把命中结果发回来。走 PeerJS 的 WebRTC 数据通道，点对点直连，不需要自建服务器。

**敌人按最近玩家选目标**：房主侧每个敌人在每次更新时，会在房主和队友之间挑离自己最近的活人（带 25% 滞回，不会来回跳）作为目标，巡逻、索敌、开火、近战、追击都对这个人生效；两人都活着时敌人会分头追击，一人倒下后全部转向另一人。敌人命中队友的伤害由房主判定，发给队友本机，走游戏自带的扣血、受击反馈和死亡流程。机械飞鸥的弹丸和自爆爆炸也会伤到队友；队友开枪的枪声会引来房主侧的敌人。实现方式：给队友造一个代理玩家，在每个敌人 `_update` 的那一刻把 `G.player` 临时换成最近的活人，结束后换回，不改游戏本体。

**任务进度同步**：三处中继的切断双向同步——任一人切断，另一端立刻看到中继变灰、进度加一并收到电台和提示；两人同时切同一个中继也不会重复。波次由房主权威生成：不论谁切断中继，房主这边都会按原逻辑刷出下一波，敌人再经状态包同步给队友。房主每 2 秒（以及队友刚加入时）广播一次已切断列表，中途加入或漏包都能补齐。**撤离结算共享**：任一人成功撤离，另一人也同时进入撤离结算。实现方式：游戏本体的中继切断函数没有导出，改为把目标中继临时排到最前再调 `G.game.debugCut()`，让游戏自己走完整流程；撤离则把另一端玩家挪到撤离点，由本体自己判定结算。

**已知边界**：队友被击倒后只在自己这边显示失败画面（没有「两人都倒才算失败」的共享失败）；一方在任务中途点「重新部署」时，另一端不会跟着重置；波次出生点按房主位置选取；队友的命中结果依赖房主回包，有一帧左右的延迟。

**队友人物（v2）**：程序化特种兵，约 1.79m 的真实人体比例，旋转体与椭球拼出躯干、四肢、头颈，带迷彩与织带贴图（代码生成）、战术背心、背包、头盔护目镜、手套和步枪。动作由骨骼层级 + 双骨 IK 驱动：脚按步频与速度落地、不滑步，持枪时双手始终贴在枪上，另有蹲伏、冲刺、跳跃落地缓冲、开火后坐与枪口焰、受击抽动、倒地。网络里 20Hz 的位置包在渲染端平滑，速度与转身由平滑后的位置推导，不需要额外字段。代码在 `mp-src/net.js` 的「替身」一节。

依赖 PeerJS 公共信令（`0.peerjs.com`）。如果哪天这个域名不可达，需要换成自建信令服务器，只改 `mp-src/net.js` 里 `peerOpts()` 的 `host/port/path` 即可，其余逻辑不动。

## 目录结构

- `index.html` —— 成品（单文件，已注入枪械皮肤；未注入天气）
- `mp/index.html` —— 双人联机版（皮肤 + 联机层，内联 PeerJS）
- `build.ps1` —— 总构建，串联皮肤与天气两层注入（产出含天气的版本）
- `skin-src/` —— 枪械皮肤源码（`skin.css` / `skin.js` / `build.ps1`）
- `weather-src/` —— 天气系统源码（`weather.css` / `weather.js` / `build.ps1`）
- `mp-src/` —— 双人联机源码（`net.css` / `net.js` / `peerjs.min.js` / `build.ps1`）
- `CLAUDE.md` —— 协作约定（直接提交 main、每次提交同步更新记录）
- `源码结构说明.md` —— 原版源码的技术档案（渲染管线、参数表、子系统、运行时抓手）

## 构建

原版不入库，按你本地存放位置传 `-BaseHtml`。每次从原版重新注入，不在成品上叠加，任一层检测到重复标记都会报错拒绝。

只构建当前上线的这一版（皮肤，不含天气）：

```powershell
pwsh ./skin-src/build.ps1 -BaseHtml <未打补丁的原版.html> -OutHtml ./index.html
```

要连天气一起构建，用仓库根的总构建：

```powershell
pwsh ./build.ps1 -BaseHtml <未打补丁的原版.html> -OutHtml ./index.html
```

要构建双人联机版（以当前离线成品为基底，再注入联机层）：

```powershell
pwsh ./mp-src/build.ps1 -BaseHtml ./index.html -OutHtml ./mp/index.html
```

联机层自检（验证信令与数据通道，不需要两台机器）：

```
mp/index.html?selftest=1
```

页面标题变成 `SELFTEST:OK` 即表示信令可达、通道双向可用。
